# tpt-concord-fuzz

Specification-driven fuzzing: state-transition-aware generation, corpus management, reproducible failures.

Part of [TPT Concord](https://github.com/tpt-solutions/tpt-concord) — the evidence and conformance layer that
connects specifications, claims, proofs, tests and release decisions.

## Overview

`tpt-concord-fuzz` — specification-driven fuzzing (spec §5).

- **state-transition-aware**: sequences are generated by walking a
  reference model (via `tpt-concord-property::stateful_sequence`), so the
  fuzzer spends its budget on inputs the specification says are reachable;
- **invariant checks**: the caller supplies the check executed over every
  generated sequence (typically: run the implementation, verify
  invariants/`conformance` after each step);
- **corpus management**: a directory-backed corpus of interesting inputs,
  content-addressed and used to seed campaigns;
- **reproducible failures**: every failure is minimized (shrunk), stored
  as JSON with its seed, and re-runnable bit-for-bit.
